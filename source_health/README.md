# MONEY MASTER OS V2 — P1 SOURCE HEALTH

Purpose: centralize collector freshness, workflow status, data-quality checks and `last_good` pointers without changing any MASTER's analytical conclusion.

## What this layer does
- Reads existing collector state files.
- Reads latest GitHub Actions run status for each registered collector.
- Normalizes each source to: `HEALTHY | DEGRADED | STALE | FAILED | MISSING | UNKNOWN`.
- Emits explicit reason codes such as `STATE_STALE`, `LATEST_WORKFLOW_FAILED`, `STATE_FILE_MISSING`, `QUALITY_CHECK_FAILED`.
- Builds a per-MASTER DATA HEALTH summary only.
- Maintains a compact `last_good` pointer for sources that were actually HEALTHY.
- Appends monthly event history only when source status/reason changes.

## What this layer NEVER does
- No price direction.
- No LONG/SHORT score.
- No Permission.
- No Entry/SL/TP/R:R.
- No replacement of stale data with `last_good` and calling it current.
- No automatic veto because an optional source is N/A.
- No cross-MASTER conclusion dependency.

## Files
- `registry.json`: monitored collector registry, freshness thresholds, quality checks, MASTER impact classification.
- `collector.py`: standard-library health normalizer.
- `output/latest.json`: latest central Source Health snapshot, generated by workflow.
- `state/last_good.json`: compact last-known-healthy pointers, generated by workflow.
- `events/YYYY-MM.jsonl`: status-change-only history, generated by workflow.

## MASTER impact labels
- `CORE`: important data availability for that MASTER; bad health reduces data-health availability.
- `OPTIONAL`: useful confirmation; bad health lowers coverage but must not auto-block a MASTER.
- `CONTEXT`: informational context only.

Impact labels describe DATA AVAILABILITY only. They are not MASTER score weights.

## Freshness model
Each source has `warn_after_minutes` and `stale_after_minutes` based on its collector cadence.
- before warning threshold: normally HEALTHY if quality checks pass.
- after warning threshold: DEGRADED.
- after stale threshold: STALE.
- failed latest workflow: FAILED.
- missing state file: MISSING.

## last_good policy
`last_good` is a pointer to the last state timestamp observed while a source was HEALTHY. It exists for diagnostics and controlled fallback decisions only. A MASTER must still obey its own freshness rules. `last_good` is never silently promoted to a current fact.

## Schedule
`.github/workflows/source_health_hourly.yml` evaluates health every hour at minute 05. This intentionally evaluates the previous collector cycle after the repository's staggered hourly collectors have had time to finish.
