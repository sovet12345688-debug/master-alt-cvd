# MONEY MASTER OS V2 — P1 SOURCE HEALTH

Purpose: centralize collector freshness, workflow status, data-quality checks and `last_good` pointers without changing any MASTER's analytical conclusion.

## What this layer does
- Reads existing collector state files.
- Reads latest GitHub Actions run status for each registered collector.
- Normalizes each source to: `HEALTHY | DEGRADED | STALE | FAILED | MISSING | UNKNOWN`.
- Emits explicit reason codes such as `STATE_STALE`, `LATEST_WORKFLOW_FAILED`, `STATE_FILE_MISSING`, `QUALITY_CHECK_FAILED`.
- Builds a per-MASTER **registered-source health** summary only.
- Maintains a compact `last_good` pointer for sources that were actually HEALTHY.
- Appends monthly event history only when source status/reason changes.
- Builds a dedicated MASTER MARKET operational board with exactly four user-facing states: `CURRENT OK | HISTORY RECOVERING | STALE | FAILED`.

## MASTER MARKET integrated health board
The dedicated board is generated by `source_health/market_integrated_health.py` after the central Source Health snapshot is refreshed.

It monitors the five recovery-sensitive MARKET components directly:
- Data Vault
- Stablecoin Windows
- Derivatives
- Actor Retail
- Yen Carry

It also surfaces non-healthy registered MARKET sources from the central Source Health output so unrelated source failures are visible next to the recovery-sensitive components.

Four operational states:
- `CURRENT OK`: current data is fresh and required current checks pass.
- `HISTORY RECOVERING`: current data is usable, but one or more actual comparison windows are still rebuilding from real observations.
- `STALE`: output or upstream evidence is older than its allowed freshness threshold.
- `FAILED`: current collection/output/schema/quality is unusable or missing.

Precedence is `FAILED > STALE > HISTORY RECOVERING > CURRENT OK`.

A `HISTORY RECOVERING` status must never trigger synthetic backfill or interpolation. Current values may remain usable while missing comparison windows continue to accumulate naturally.

Outputs:
- `output/master_market_integrated_health.json`: machine-readable board.
- `output/master_market_integrated_health.md`: compact GitHub-readable dashboard.

The board is operational diagnostics only. It never changes MASTER MARKET score, direction, WATCH, Risk Veto, entry, stop or target.

## Critical naming rule
`registered_source_health_pct` is NOT MASTER Coverage, not confidence and not an analytical score. It only summarizes the health of the shared/repository sources currently registered for that MASTER. A MASTER may use many direct per-run sources that are not represented here.

Example: ALT1 can show a low `registered_source_health_pct` if only a small number of shared GitHub collectors are registered and one is down. That must never be read as `ALT1 Coverage=low` or as a reason to reject a setup by itself.

## What this layer NEVER does
- No price direction.
- No LONG/SHORT score.
- No Permission.
- No Entry/SL/TP/R:R.
- No MASTER Coverage replacement.
- No replacement of stale data with `last_good` and calling it current.
- No automatic veto because an optional source is N/A.
- No cross-MASTER conclusion dependency.

## Files
- `registry.json`: monitored collector registry, freshness thresholds, quality checks, MASTER impact classification.
- `collector.py`: standard-library health normalizer.
- `market_integrated_health.py`: MASTER MARKET four-state integrated operational board builder.
- `output/latest.json`: latest central Source Health snapshot, generated by workflow.
- `output/master_market_integrated_health.json`: latest MASTER MARKET integrated health board.
- `output/master_market_integrated_health.md`: compact human-readable MASTER MARKET board.
- `state/last_good.json`: compact last-known-healthy pointers, generated by workflow.
- `events/YYYY-MM.jsonl`: status-change-only history, generated by workflow.

## MASTER impact labels
- `CORE`: important data availability for that MASTER; bad health reduces registered-source availability.
- `OPTIONAL`: useful confirmation; bad health reduces registered-source health but must not auto-block a MASTER.
- `CONTEXT`: informational context only.

Impact labels describe DATA AVAILABILITY only. They are not MASTER score weights.

## Freshness model
Each source has `warn_after_minutes` and `stale_after_minutes` based on its collector cadence.
- before warning threshold: normally HEALTHY if quality checks pass.
- after warning threshold: DEGRADED.
- after stale threshold: STALE.
- failed latest workflow: FAILED.
- missing state file: MISSING.

The MASTER MARKET integrated board additionally applies component-specific freshness rules already enforced by the underlying collectors/adapters, including Actor Retail upstream freshness and Yen Carry source-specific daily freshness.

## last_good policy
`last_good` is a pointer to the last state timestamp observed while a source was HEALTHY. It exists for diagnostics and controlled fallback decisions only. A MASTER must still obey its own freshness rules. `last_good` is never silently promoted to a current fact.

## Schedule
`.github/workflows/source_health_hourly.yml` evaluates health every hour at minute 05. This intentionally evaluates the previous collector cycle after the repository's staggered hourly collectors have had time to finish. The same workflow then refreshes and validates the MASTER MARKET integrated health board.
